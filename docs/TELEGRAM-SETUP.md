# Подключение Telegram для заказов

Этот файл нужен владельцу заведения или человеку, который настраивает production. Токен бота нельзя отправлять в чат, коммитить в Git или помещать в `VITE_*`.

## 1. Создать бота

В Telegram открыть официальный `@BotFather`, выполнить `/newbot`, сохранить выданный token только в менеджере секретов Vercel. На рабочем устройстве открыть созданного бота и нажать **Start**.

## 2. Выбрать один рабочий чат

MVP отправляет заказы в один numeric chat ID: личный чат сотрудника или закрытая рабочая группа. После сообщения в выбранном чате временно запросить:

```text
https://api.telegram.org/bot<TOKEN>/getUpdates
```

В ответе найти `message.chat.id`. Не публиковать весь ответ: в нём могут быть имена, usernames и текст сообщений. Если включён webhook, сначала удалить его через BotFather/API или использовать отдельный тестовый бот — `getUpdates` не работает одновременно с активным webhook.

## 3. Сохранить серверные секреты

В Vercel → Project → Settings → Environment Variables добавить только для Production:

```text
TELEGRAM_BOT_TOKEN=<token>
TELEGRAM_CHAT_ID=<numeric chat id>
UPSTASH_REDIS_REST_URL=<https url>
UPSTASH_REDIS_REST_TOKEN=<token>
ORDER_HASH_SECRET=<случайная строка не короче 32 символов>
ORDER_ALLOWED_ORIGINS=https://подтверждённый-домен.example
ORDERS_ENABLED=false
```

Preview оставить с `ORDERS_ENABLED=false` или подключить отдельный тестовый бот и отдельную Redis-базу. После изменения env нужен redeploy.

## 4. Проверить бота без заказа

С локальной машины с env, которые не попадут в Git, проверить только доступность credentials:

```powershell
$env:TELEGRAM_BOT_TOKEN='...'
node scripts/check-telegram.mjs
```

Скрипт вызывает только `getMe`, проверяет `chat_id` числом и печатает имя бота без токена. Он не отправляет сообщения и не читает историю чата.

## 5. Провести smoke test

После заполнения подтверждённого меню включить в тестовом окружении `ORDERS_ENABLED=true`, затем оформить один заказ самовывозом. Сотрудник должен увидеть одно сообщение в выбранном чате и перезвонить клиенту. Повторная отправка того же заказа не должна создать второе сообщение. Доставку включать только после заполнения зон, стоимости, минимальной суммы и времени.

После smoke test:

1. проверить, что token не отображается в исходном HTML, frontend bundle, логах и Git;
2. установить `ORDERS_ENABLED=true` только Production;
3. при утечке немедленно перевыпустить токен через BotFather;
4. сохранить рабочий chat ID и ответственного за звонки в закрытой документации заведения.
