# Шаурма у Айхана

Mobile-first сайт заведения в Одессе, Украина. Сохранены тёмная палитра с лаймовым акцентом, hero и локальная корзина. Интерфейс на украинском; названия и описания меню сохранены в языке источника.

Текущий статус: презентационная frontend-версия. **Реальный канал заказа ещё не подключён.** `ownerVerified: false`, `indexable: false`; сайт не открыт для индексации. Backend, база данных, оплата, авторизация и Telegram-бот отсутствуют.

## Стек

React 19, TypeScript, Vite 8, Tailwind CSS 4, два локальных компонента shadcn/Base UI, Lucide. Проверки: TypeScript, Oxlint и встроенный Node test runner. ESLint не используется.

При сборке React рендерит начальную страницу в статический HTML. В браузере React подключает навигацию, поиск и корзину. Сервер для работы сайта не нужен; SSR используется только во время сборки.

## Установка и запуск

Node.js 24.x LTS (та же основная версия, что проверена локально и используется для Vercel), pnpm **11.19.0** из `packageManager`. Например, установите pnpm через `npm install -g pnpm@11.19.0`, если он отсутствует.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Откройте [локальный сайт](http://127.0.0.1:3000). Vite слушает только loopback. Для запуска из Windows с установленными зависимостями есть `start-local.ps1`: скрипт находит обычный Node или bundled runtime Codex и не устанавливает пакеты автоматически.

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm start
```

`pnpm start` показывает содержимое `dist` на порту 3000. Перед запуском остановите dev-сервер на том же порту. Это локальная проверка production-сборки, не публичный production-сервер. На хостинг загружается `dist` ([документация Vite](https://vite.dev/guide/static-deploy.html)).

`pnpm test` самостоятельно собирает тесты в `.test-build`: предварительная сборка сайта не требуется. Проверяются повреждённое сохранение корзины, лимиты количества, расчёт суммы, ссылки каналов заказа, целостность меню и рендер без браузера. `pnpm build` отдельно проверяет сгенерированные metadata, запрет индексации, локальные ассеты и отсутствие временных каталогов в результате.

| Тип продукта, категории, ссылка и дата источника             | `data/menu.ts`                                     |
| Исходный снимок Glovo для сверки                             | `data/glovo-snapshot.json`                         |

Неизвестные контакты должны оставаться `null`. Не вставляйте номер или username «для примера» в активный бизнес-конфиг. Для карты можно заполнить `googleMapsUrl` и, отдельно, `mapEmbedUrl` действительным URL встраивания. Сейчас показывается адрес и ссылка на поиск Google Maps; фиктивного iframe нет.

`openingHours` — строка в формате schema.org, например синтаксис `Mo-Su HH:MM-HH:MM`, с реальными подтверждёнными часами. Номер телефона храните в международном формате. Контактные сведения публикуются в frontend и не являются секретами.

## Меню Glovo

Снимок от 09.09.2026: 126 исходных строк, 117 позиций после объединения повторов с одинаковыми названиями и ценами; 13 категорий. Разные цены одного названия сохранены как отдельные позиции. У 13 позиций есть примечания о расхождениях источника. Акционные цены Glovo не объявляются ценами непосредственно в заведении. Статус доступности неизвестен (`available: null`); установите `false`, чтобы запретить добавление недоступной позиции.

116 локальных WebP-фотографий; у одной позиции нет загруженного фото — показывается нейтральная иконка. Hero — AI-иллюстрация; видимая подпись поверх изображения удалена по просьбе пользователя. До публичной публикации согласуйте с владельцем меню, цены, состав и использование изображений.

Обычное редактирование: меняйте `data/menu.json`, сохраняйте стабильный `id`, чтобы не ломать корзины. При смене ID старые строки автоматически исключаются из сохранённой корзины.

Для повторной обработки исходного снимка:

```sh
python scripts/normalize-menu.py
# Опционально: нужны Python + Pillow, доступ к исходным фотографиям
python scripts/download-menu-images.py
python scripts/normalize-menu.py
```

Нормализация **перезаписывает меню из снимка**: сначала сохраните ручные изменения в Git, затем проверьте diff. Отсутствующие фотографии получают пустой путь; повторная нормализация после загрузки подхватит их. Эти скрипты не запускаются при сборке. Служебные материалы `work/` для них не нужны.

## Корзина и заказ

Корзина хранит ID и количество в `localStorage` под ключом `aykhan-cart-v2`, синхронизируется между вкладками и работает в памяти при недоступном хранилище. Лимит — 20 порций одной позиции; суммы считаются в копейках. Цена всегда берётся из текущего меню.

В `config/business.json` выберите `orderChannel`:

- `none`: честное сообщение о неподключённом канале, копирование списка и адрес.
- `whatsapp`: заполните `whatsapp` международным номером. Откроется чат с текстом заказа; посетитель отправляет его сам.
- `telegram`: заполните `telegram` username без `@` и URL. Посетитель копирует список и открывает чат.
- `phone`: заполните `phone`. Посетитель может позвонить и уточнить список.

Ни один канал не отправляет заказ автоматически и не сообщает о принятом заказе. Если clipboard недоступен, появляется поле для ручного копирования. Проверка наличия, доставка и окончательная сумма согласуются с заведением.

Для будущего API/Telegram Mini App сохраняйте `id + quantity` как входные данные заказа, а цены и доступность перепроверяйте на сервере. Секрет бота никогда не должен попасть в `VITE_*`, JSON или frontend. На этом этапе сервер не добавляется.

## Environment и SEO

Для локальной сборки переменные не обязательны. `.env.example` содержит только пустой `SITE_URL`; можно скопировать его в `.env.local`. На Vercel задайте переменную в настройках проекта. Она читается во время сборки, а не во время выполнения страницы.

`SITE_URL` — подтверждённый HTTPS-origin без пути. При отсутствии переменной можно использовать `business.siteUrl`; пока оба пустые, canonical и sitemap не создаются. Metadata, favicon и Restaurant JSON-LD формируются без выдуманных рейтингов и контактов.

Индексация разрешается только при одновременном наличии домена и `ownerVerified: true`, `indexable: true`. Пока владелец не подтвердил данные, **оба флага оставьте false**, в том числе на preview. `noindex` не является защитой приватной информации; публичная презентация должна содержать только допустимые для публикации данные.

## Deployment на Vercel

1. Сохраните исходники в GitHub, не добавляя `.env`, `node_modules`, `dist`, `.prerender`, `.test-build` и `work`.
2. Импортируйте репозиторий в Vercel, выберите Node 24.x.
3. Используйте `vercel.json`: framework Vite, install `pnpm install --frozen-lockfile`, build `pnpm run build`, output `dist`.
4. Включите для build `ENABLE_EXPERIMENTAL_COREPACK=1`, чтобы Vercel использовал закреплённый `pnpm@11.19.0` из `packageManager`. При CLI deployment передайте `--build-env ENABLE_EXPERIMENTAL_COREPACK=1`. Создайте preview с выключенной индексацией; проверьте навигацию, корзину, изображения и `/robots.txt` на выданном URL.
5. После подтверждения владельцем заполните канал заказа, часы и домен, пересоберите и проверьте реальный контакт вручную. Индексацию включайте отдельным осознанным изменением.

Конфигурация следует [документации Vercel для Vite](https://vercel.com/docs/frameworks/frontend/vite). Актуальный временный preview уже опубликован: [preview-source-auparodre-artemkovko-3474.vercel.app](https://preview-source-auparodre-artemkovko-3474.vercel.app/). Deployment создан без `--prod` и без custom domain, с `target: null`; индексация остаётся выключенной. Отдельных маршрутов приложения нет: используются секции с якорями; сгенерирована страница `404.html`.
